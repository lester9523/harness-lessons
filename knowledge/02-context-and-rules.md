# 给 Agent 足够而清晰的信息

先让当前任务能找到正确资料，再逐步展开细节。规则除了说明做法，还要说明冲突时的优先级；资料除了有内容，还要知道是否仍然有效。

<a id="principles"></a>
## 方法一  把隐含取舍写成原则

**适用现象：** Agent 理解了目标，但反复违反自己认为理所当然的约定。

先描述一个实际冲突，再写清选择、理由和适用范围。例如“简洁与信息完整冲突时，保留影响决策的事实；可以压缩背景，不能删掉限制条件”。这比同时要求“准确、全面、简洁”更容易执行。

**操作顺序：** 找出反复出现的分歧；确认用户真实的优先级；记录原则及理由；提供一个合适和一个不合适的例子；将可机械判断的部分补成检查。

原则可以长期存在，某次任务的特殊权衡则留在决策记录。不要将一次偏好扩展成所有场景的永久规则。

**验收：** 给出一个新的冲突例子，检查 Agent 是否能根据原则解释自己的选择，而不是只复述规则。

```text
列出这项任务中可能互相冲突的要求。依据已经确认的原则说明先保住什么、可以妥协什么，以及理由和适用范围。没有明确依据的重大取舍交给我判断，不自行写成长期规则。
```

<a id="source-maintenance"></a>
## 方法二  为知识建立维护责任

**适用现象：** 按文档严格执行，结果仍与现实不符。

对影响结果的重要知识记录五项：内容、权威出处、核实日期、适用范围、重新核实的触发条件。触发条件可以是来源改版、相关工具升级、用户改口或实际行为与记录不符。

使用时先检查是否触发更新。没有触发且任务低风险，可以使用已确认的知识；变化频繁或影响较大时，应重新核实。记录缺失时标出不确定性，不把“仓库里写着”当作正确的充分证据。

**辅助示例：** 一份流程说明来自某次讨论，但执行人已经调整。应更新责任分配并保留变更理由，而不是继续按旧文档安排任务。

**验收：** 随机选一个关键结论，能找到出处、核实时间及失效条件；仅改笔记措辞不能刷新来源核对日期。

<a id="rule-maintenance"></a>
## 方法三  定期治理规则

**适用现象：** 规则不断增加，“但是、除非”越来越多，失败后很难定位冲突来源。

1. 盘点规则，标出适用范围与优先级。
2. 合并重复项，识别相互矛盾或已经过时的项。
3. 根据已确认的优先级裁决；无法裁决的冲突报告给人。
4. 入口只保留关键原则和资料位置，详细操作按任务读取。
5. 用曾经出错的任务复查，确认清理没有删掉有效约束。

不要仅按文件长度判断好坏，也不要为了精简删除必要的验收与例外。自然语言规则仍可能被遗漏；重要约束需要可靠的检查或权限边界配合。

<a id="context-budget"></a>
## 方法四  给上下文安排预算

**适用现象：** 资料给得越多，Agent 越分不清重点；反复搜索不相关文件。

先提供目标、完成标准、资料索引与必要现状，再按执行步骤读取原文。

| 动作 | 决定什么 | 不要丢掉什么 |
| --- | --- | --- |
| 筛选 | 与当前任务有关才提供 | 会改变结论的限制和例外 |
| 分层 | 先给结论与入口，再展开证据 | 从摘要回到原始依据的路径 |
| 按需加载 | 走到相应步骤再读详细材料 | 索引、文件位置和使用条件 |
| 压缩 | 保留恢复工作需要的信息 | 目标、约束、关键决策、验证与未决问题 |

**辅助示例：** 要整理一篇文章时，先给文章本身与整理标准，不默认加载全部课程、历史对话和团队制度。发现涉及旧概念时再补相应知识。

**验收：** Agent 能说明当前使用了哪些材料、为什么相关；压缩后仍能按同一目标继续工作。上下文容量大，并不意味着信息都值得加载。

```text
先读当前任务必需的入口与索引，列出需要展开的资料及用途，再按需读取。保留关键约束和来源；不要为了充分了解而遍历全部历史。如果资料冲突，先报告冲突和核实办法。
```
