# 让工作接得上让记录值得信任

跨会话接续的目标是恢复工作，而非保留全部聊天。记录应该让下一轮知道目标、进度、证据和理由，也能分清事实与临时判断。

<a id="checkpoint"></a>
## 方法一  在阶段边界建立检查点

**适用现象：** 对话越来越长，执行后期开始省略验证或忘记早期约束；任务被打断后难以继续。

在阶段完成、切换工作重点、即将处理大量资料或需要换会话时，保存以下信息：

- 目标、范围和仍然有效的关键约束。
- 已完成与未完成的步骤，附实际产物位置。
- 关键决策与理由，不仅保留结论。
- 已做的验证及结果，未验证的部分。
- 未决问题、阻塞点，以及一个明确的下一步。

保存后可以缩小当前子任务或换会话继续。不要为了维持一个长会话，把更多资料继续堆进去；也不要把一次匆忙结束直接断言为模型内部的某个缺陷，应结合实际上下文负担与行为检查。

**验收：** 不查看原聊天，仅依据检查点和当前文件，能否正确说明“做到哪里、为什么、下一步做什么”。

<a id="handoff"></a>
## 方法二  交接时先核实再继续

新会话先读入口、状态和当前任务相关内容，再核对实际文件、版本与环境。交接记录可能过时，不能覆盖现状。

```text
目标与范围：
关键约束：
已完成及产物位置：
已做验证及结果：
决策与理由：
未决事项及阻塞点：
下一步：
记录时间与适用范围：
```

发现记录与现状不符时，先标明差异和依据；会改变后续行为的重要差异需要解决，不能直接按旧状态继续。

```text
先读项目入口和交接记录，核对当前文件及相关状态。说明仍然有效的目标、已经完成的工作、验证证据、未决问题和下一步。如果记录与现状冲突，先核实差异，再继续。
```

<a id="state-partition"></a>
## 方法三  临时数据与长期知识分开

**适用现象：** 一次猜测被后续会话反复引用，错误结论越来越像确定事实。

| 信息 | 放在哪里 | 何时可以用于长期决策 |
| --- | --- | --- |
| 草稿、原始日志、临时推理 | 临时工作区 | 先检查与提炼，不直接作为长期结论 |
| 待验证假设 | 明确标注的未决记录 | 取得相应证据后再更新状态 |
| 已确认事实 | 有来源和时间的知识记录 | 在适用范围内使用，条件变化时复核 |
| 用户偏好 | 带场景和来源的偏好记录 | 用户已明确表达，不扩大为无条件规则 |
| 决策 | 带理由与适用范围的决策记录 | 在原决策范围内使用，条件变化时重评 |

工具返回“完成”，只代表它报告了某个执行状态。仍需确认它实际处理的对象和数量，不能直接把业务目标记录为达成。

**修复旧污染：** 找出结论最早的依据；隔离无依据的结论；核对受影响的后续结果；更新长期记录并保留纠正原因。只修当前输出，下一轮仍可能读到同一错误。

## 方法四  给执行中产生的新知识找归处

任务收尾时分别清点：用户的新偏好、执行中的发现、作出的决策。记录来源、时间、理由与范围。负责整体工作的环节再决定它们进入规则、领域资料还是决策记录，避免每个子任务随意增加长期规则。

发生冲突时先比较适用范围，再比较来源、确认程度与时间。用户后来对某个场景允许例外，不意味着所有场景都已取消旧约束；模型新猜测也不能因为时间更近就覆盖有证据的事实。

**验收：** 下一项相关任务能取到正确记录；无关任务不会被这项局部偏好误导。

## 使用边界

记录不等于自动记忆。需要有明确入口、读取动作和更新责任。公开仓库保留可分享的结论及必要依据，不保存原始私密日志。是否写入本仓库，遵循当前任务授权。
